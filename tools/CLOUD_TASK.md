# Обновяване на трафика и пътната обстановка (облачна задача)

Тази инструкция се изпълнява от облачна задача на Claude на всеки 15 минути.
Работи в това хранилище (vasiliyaa/tol-marshruti), клон `main`. Сайтът е https://vasiliyaa.github.io/tol-marshruti/.

## 1. Започни от най-новото
```
git checkout main && git pull -q --rebase origin main
```

## 2. Пътна обстановка → `incidents.json`
`incidents.json` е JSON списък от събития, подреден по `id`. Пиши го с отстъп 1 и подредени ключове
(`json.dump(..., ensure_ascii=False, indent=1, sort_keys=True)` + нов ред накрая).

1. Отвори с WebFetch https://www.api.bg/index.php/bg/pytna-obstanovka/ и извлечи всички текущи събития: затворени пътища,
   катастрофи, аварирали коли, ограничения, ремонти, забрани за тежкотоварни. Прочети и последните новини на същия сайт
   за ремонти и забрани с конкретни дати. За всяко събитие запиши пътя, мястото/км, вида, часа и срока.
2. Събитията с `id`, започващо с `api-`, са от АПИ. Другите са добавени от хора: НЕ ги пипай, освен ако имат `until`
   по-старо от днешната дата (Europe/Sofia) — тогава ги махни.
3. За всяко текущо събитие от АПИ направи запис с `id` `api-<YYYY-MM-DD>-<кратък-латински-ключ>`
   (напр. `api-2026-10-30-i6-kamartsi`). Ако събитието вече е в списъка, обнови съществуващия запис, не прави нов. Полета:
   - `type`: `closed` (затворен път), `accident` (катастрофа/авария/една лента, закъснение), `works` (ремонт, бавно движение),
     `truckban` (забрана или пренасочване за камиони над 12 т)
   - `road`: точно `I-1`…`I-9` за I клас, `II-18`, `II-81` и т.н. за II клас, `А-1`…`А-6` за магистрали (с КИРИЛСКО „А“);
     празен низ за III клас или ако е неясно
   - `title`: кратко заглавие на български; `note`: подробности на български (лентата, пренасочвания)
   - `lon`, `lat`: координати на мястото, по възможност върху самия път (по населеното място/км; провери с WebSearch, ако не
     си сигурен). Тунели на А-2: Витиня 23.7957,42.783; Топли дол 23.7968,42.838; Ечемишка 23.791,42.857;
     Правешки ханове 23.913,42.915
   - `radius`: 1.5 (км; 2–3 за по-дълги участъци); `delay`: минути закъснение (катастрофа в една лента 20, пълно затваряне 0)
   - `time`: напр. `"30.10 11:12"`; `until`: `"YYYY-MM-DD"` (последният ден, в който важи; за инциденти без срок —
     днешната дата) или `days`: `["YYYY-MM-DD", ...]` за забрани в конкретни дни
   - `source`: `"АПИ, актуална пътна обстановка, DD.MM.YYYY"` или `"АПИ, новини, DD.MM.YYYY"`
4. Махни записите `api-…`, които АПИ вече не показва и чийто срок е изтекъл. Запази тези със срок в бъдещето.
5. Ако сайтът на АПИ не се отваря, НЕ променяй `incidents.json`.

## 3. Трафик → `road_live.js`
```
python3 tools/update_live.py
```
Скриптът тегли данните на БГТОЛ и пише `road_live.js` заедно със събитията от `incidents.json`. Ако БГТОЛ не отговори,
пази последния трафик — това е нормално, продължи.

## 4. Качи
```
git add incidents.json road_live.js
git diff --cached --quiet || git -c user.name=tol-cloud -c user.email=tol-cloud@users.noreply.github.com commit -q -m "Трафик и пътна обстановка (облак)"
git push -q origin HEAD:main || (git pull -q --rebase origin main && git push -q origin HEAD:main)
```
Пускай директно в `main`, без нов клон и без pull request.

## 5. Отговор
Един ред: колко точки трафик и от кой час (или че БГТОЛ не отговори), колко събития са добавени/обновени/махнати
(или „без промени“) и дали е качено в GitHub.

Не променяй други файлове в хранилището.
